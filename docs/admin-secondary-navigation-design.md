# Router Admin 二级导航与内容分层设计

状态：已实现并通过本地验证，待设备部署
实现、设计与 Review：Codex

## 1. 设计结论

Router Admin 保留现有左侧一级导航，在工作区标题下增加“当前模块专属”的横向二级导航。点击二级项后，只渲染对应子页内容，不再把该一级模块的全部面板纵向铺开。

“分离但不过分隔离”通过三层职责实现：

1. 一级导航回答“我在哪个业务模块”；
2. 二级导航回答“我在处理该模块的哪类任务”；
3. 页面内 tab、筛选器和折叠项只切换当前任务的数据视角。

跨子页只保留一条轻量的模块上下文，不保留大卡片。上下文最多展示 2–4 个关键状态和当前模块告警；具体图表、表格、表单只出现在所属子页。

## 2. 当前问题

现有 `admin/frontend/app/page.tsx` 只维护一级 `active` 状态。一级切换后，`Network`、`Clients`、`Services`、`MihomoManager`、`System` 等组件会一次性返回该模块下的所有面板。

影响包括：

- 用户点击一个功能后仍需在长页面中寻找目标区域；
- “代理”页同时展示运行状态、CPA、模式、节点、测速、端口、订阅和流量审计，任务边界最混乱；
- 同一屏中同时出现监控、配置和高风险操作，主次关系不清楚；
- 不相关的轮询和复杂表格仍在同一页面生命周期中运行；
- 浏览器返回、刷新和复制链接不能恢复到具体子页；
- 移动端滚动距离过长，底部一级导航与页面内部 tab 的层级感较弱。

## 3. 导航形态

### 3.1 桌面与平板

- 左侧栏继续作为一级导航，不在左栏展开树形子菜单。
- 二级导航放在页面 `topbar` 下、模块内容上方，和内容列同宽。
- 使用单行横向 tab bar，当前项以高对比底色和细下划线/内描边表达。
- 二级导航在页面滚动后可吸附在工作区顶部；吸附时保持紧凑，不重复显示大标题。
- 二级项只使用短文本，不为每个子页增加图标。

不采用左侧树形菜单的原因：当前已有 9 个一级入口，220px 侧栏高度和 78px 平板折叠态都不适合继续塞入多层菜单；一级与二级放在不同轴向也更容易建立层级。

### 3.2 手机

- 底部栏仍只承载一级导航。
- 二级导航位于标题下方，单行横向滚动，首尾留出内边距提示可滑动。
- 当前项滚入可视区域；触控目标高度至少 44px。
- 不把二级菜单塞入抽屉，也不隐藏到“更多”按钮中。
- tab 文案保持 2–6 个汉字，不换行。

### 3.3 页面结构

```text
一级侧栏 / 手机底栏
  └─ 页面标题 + 全局操作（刷新、登录状态）
      └─ 二级导航（仅复杂模块显示）
          └─ 模块上下文条（状态、关键告警、必要的跨页动作）
              └─ 当前子页内容（只挂载这一份）
                  └─ 局部 tab / 筛选 / 折叠（只影响当前工具）
```

## 4. 信息架构

### 4.1 不增加二级导航的一级页

- **总览**：本身就是跨模块摘要和快捷入口。
- **存储**：磁盘容量与 USB 拓扑仍属于一个短任务页，继续同页展示。
- **日志**：日志来源切换是数据筛选，不是独立任务；保留为页内控件。

短页面不为了形式统一而强行拆分。

### 4.2 网络

默认子页：`运行状态`

| 子页 | 包含内容 | 不包含内容 |
| --- | --- | --- |
| 运行状态 | WAN/LAN 吞吐趋势、接口卡片、地址/速率/载波 | 网络配置表单 |
| 接口配置 | WAN/LAN 配置记录、编辑与保存、安全说明 | 吞吐图、全部接口卡片 |

共享上下文：WAN 状态、LAN 状态、当前 WAN/LAN 接口名。保存成功后留在“接口配置”，只刷新状态条。

### 4.3 客户端

默认子页：`流量概览`

| 子页 | 包含内容 |
| --- | --- |
| 流量概览 | WAN/内网实时速率卡、累计量、最近 10 分钟趋势 |
| 设备管理 | 已发现客户端表、排序、静态租约编辑、单设备 TUN 绕过 |

共享上下文：在线设备数、当前 WAN 下载/上传速率。设备编辑草稿在两个子页切换时不得丢失；离开一级“客户端”前若存在未保存编辑，使用现有页面内提示或显式放弃机制，不能静默丢弃。

### 4.4 服务

默认子页：`全部服务`

| 子页 | 包含内容 |
| --- | --- |
| 全部服务 | Runit 服务卡、打开网页、日志、启动/停止/重启 |
| Tailscale | Tailscale 状态、地址、控制动作 |
| Aria2 | 下载速率、任务列表和进度 |

共享上下文：运行服务数/总数、异常服务数。总览中的服务卡可以深链到 Tailscale 或 Aria2 子页。

### 4.5 代理

默认子页：`运行概览`

| 子页 | 包含内容 |
| --- | --- |
| 运行概览 | Mihomo hero、实时上下行/连接数、CPA 集成、代理模式 |
| 策略与节点 | 代理组与节点选择；当前选择摘要 |
| 体验测速 | 快速/深度测速、进度、结果、应用候选节点 |
| 流量审计 | 审计摘要、倍率设置、清空、本工具内部的终端/订阅/节点/组/目标/时间视图 |
| 设置 | 本地服务端口、LAN/系统代理开关、订阅管理 |

共享上下文：Mihomo 运行状态、当前模式、活动订阅、当前连接数；出现采集异常或订阅失效时展示一条可点击告警，并跳转到归属子页。

边界说明：

- “流量审计”内部现有的终端、订阅、节点、代理组、目标、时间仍是局部数据视图，不能提升成二级菜单。
- “体验测速”运行在后端；离开子页不得取消任务。返回时重新读取进度与结果。
- “策略与节点”切换节点后，只更新共享上下文和该子页状态，不把测速结果或审计表格带进来。
- “设置”允许有多个紧密相关的配置面板，但不得混入监控图表。

### 4.6 系统

默认子页：`供电与电池`

| 子页 | 包含内容 |
| --- | --- |
| 供电与电池 | 供电状态、电池保护阈值、电流趋势、电池/USB 电压趋势 |
| 性能与温度 | 设备信息、CPU/内存/温度趋势、核心明细、内存明细、温区列表 |

共享上下文：电量、USB 供电状态、CPU 温度。电池保护设置只在供电子页出现。

### 4.7 远程

默认子页：`终端`

| 子页 | 包含内容 |
| --- | --- |
| 终端 | Web Terminal 工具栏和终端画布 |
| 屏幕 | scrcpy 工具栏、屏幕画布、全屏控制 |

现有 `RemoteMode` 改由统一二级导航驱动。切换时应释放上一工具的 WebSocket、decoder 和输入监听；“屏幕”沉浸模式仍可隐藏普通 topbar，但必须保留可返回“终端”的明确入口。

## 5. “不过分隔离”的连接机制

### 5.1 模块上下文条

上下文条不是另一组大卡片，而是一行状态：

```text
Mihomo 运行中  ·  Rule 模式  ·  蜂鸟云  ·  18 条连接
```

- 正常状态使用文字和小圆点，不把每项包装成卡片。
- 只展示能帮助用户判断当前模块是否正常的信息。
- 最多一个主告警；告警可跳转到负责处理它的子页。
- 子页内已经有同一数值的大型指标时，允许省略重复的上下文项。

### 5.2 任务深链

跨页按钮直接跳到目标子页，而不是只切一级：

- 总览“管理存储” → `view=storage`；
- 总览“屏幕控制” → `view=remote&section=screen`；
- 服务卡“Tailscale 详情” → `view=services&section=tailscale`；
- 代理告警“检查订阅” → `view=mihomo&section=settings`；
- 测速结果“查看当前策略” → `view=mihomo&section=policies`。

### 5.3 状态连续性

- 二级切换只卸载不可见内容 DOM；模块级数据和后端任务状态保留在稳定父组件或后端。
- 搜索、排序、筛选在同一子页内往返时保留到本次浏览会话结束。
- 未保存表单草稿不得因点击兄弟子页而静默丢失。
- 实时全局快照继续在 `Home` 层统一轮询；子页专属轮询只在需要时运行。

## 6. URL、返回键与刷新

采用查询参数，不新增物理路由，以兼容当前 Next 静态导出和设备端单页部署：

```text
/?view=mihomo&section=traffic
/?view=services&section=tailscale
/?view=remote&section=screen
```

要求：

- 用户点击一级或二级导航时使用 `history.pushState`；
- 初始加载和非法参数归一化使用 `history.replaceState`；
- 监听 `popstate`，浏览器前进/后退必须恢复一级和二级选中态；
- 刷新后恢复同一子页；
- 非法 `view` 回退到 `overview`；非法或缺失 `section` 回退到该模块默认子页；
- 不把临时筛选、排序、弹窗、表单草稿写入 URL；
- 登录完成后保留原目标参数，不强制跳回总览。

稳定 section ID：

```text
network:  status | config
clients:  traffic | devices
services: all | tailscale | aria2
mihomo:   overview | policies | speedtest | traffic | settings
system:   power | performance
remote:   terminal | screen
```

## 7. 组件实现边界

Antigravity 不应继续在 `Home` 中增加成片条件 JSX。建议增加：

- `navigation.ts`：一级/二级导航声明、默认项、参数校验；
- `SecondaryNav`：统一语义和响应式表现；
- `ModuleContextBar`：共享状态/告警容器；
- 每个复杂一级模块内部按上表拆为稳定子组件；
- 一个统一 `navigate(view, section?)` 方法，替代散落的 `setActive` / `setRemoteMode`。

数据获取原则：

- `/api/snapshot` 继续由 `Home` 统一轮询；
- Tailscale、Mihomo 测速、流量审计、日志等专属请求只由所属子页发起；
- 后台任务不得依赖组件持续挂载才能完成；
- 隐藏子页不能继续高频轮询或保留无用事件监听；
- 回到子页后立即读取一次服务端状态，再恢复合理轮询。

可以在本次重构中提取组件，但不得顺带改 API、代理策略、服务控制语义或视觉主题。

## 8. 交互和可访问性

- 二级导航使用 `role="tablist"`；按钮使用 `role="tab"`、`aria-selected`、`aria-controls`。
- 内容容器使用 `role="tabpanel"` 和对应 `aria-labelledby`。
- 左右方向键在二级 tab 间移动，Home/End 到首尾；Enter/Space 激活。
- 焦点态清晰，不能只靠颜色区分当前项。
- 切换后焦点留在所点 tab，不强制把焦点送入正文；屏幕阅读器能读出新的页面标题。
- 页面 `h1` 使用“一级 · 二级”，例如“代理 · 流量审计”；小屏可只显示二级标题，一级名保留在可访问名称中。
- 加载、空数据、失败状态由当前子页独立呈现；一个子页失败不能遮住整个一级模块。

## 9. 视觉约束

- 二级导航与现有深色、青色强调体系一致，但层级弱于左侧一级选中态。
- 不使用另一排大图标卡作为菜单。
- 二级导航与首个内容面板间距 14–18px。
- 上下文条高度控制在约 36–44px；内容换行时允许变为两行，不横向溢出。
- 页面切换不做滑入滑出动画；只允许 120–180ms 的颜色/背景过渡，避免实时仪表抖动。
- 内部数据 tab 使用更小的 pill 样式，与页面级二级导航明显区分。

## 10. 不在本次范围

- 不把页面改造成多文件 Next App Router 路由；
- 不改变登录、权限、API 或设备端部署路径；
- 不重做整体品牌、颜色或卡片视觉；
- 不新增第三层全局菜单；
- 不部署到手机、不重启服务、不修改实时代理或订阅状态；
- 不把所有短页面机械拆成二级页。

## 11. 验收标准

1. 点击任一二级项后，DOM 中只存在当前子页的主要内容；不是把其他内容用滚动定位或纯 CSS 隐藏。
2. “代理 · 流量审计”页不再出现 CPA、代理模式、节点、测速、端口和订阅面板。
3. “服务 · Tailscale”页不再出现 Aria2 与全部 Runit 服务卡。
4. “系统 · 供电与电池”页不再出现 CPU 核心、内存和温区明细。
5. 一级/二级选中态、标题和 URL 始终一致。
6. 浏览器前进、后退、刷新、非法参数回退均符合第 6 节。
7. 桌面、78px 折叠侧栏、620px 以下底栏三种布局均无重叠和横向页面溢出。
8. 手机二级导航可横向滑动，当前项自动进入可见区域，触控目标不小于 44px。
9. 键盘和屏幕阅读器语义符合第 8 节。
10. 子页切走后，其专属轮询、WebSocket 和事件监听按设计停止；进行中的后端测速任务继续执行。
11. 返回设备管理、筛选表格或配置子页时，会话内状态和未保存草稿不被静默清除。
12. 总览和告警中的深链能一次到达正确二级页。
13. 现有一级页面功能、服务操作、节点切换、测速、审计、日志和远程控制行为没有回归。
14. `npm run lint`、`npm run export` 和 `git diff --check` 通过，Chrome 87 兼容产物正常生成。
