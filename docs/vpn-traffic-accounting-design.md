# Mihomo 通用流量审计设计

状态：实现规格
目标设备：OnePlus 7 Pro 手机路由器
实现：Antigravity
设计、Review、测试与部署：Codex

## 1. 目标

在 Router Admin 中增加一个持久化流量审计模块，回答：

1. 哪个终端产生了流量；
2. 流量是 `DIRECT`、代理节点还是 `REJECT`；
3. 代理流量经过哪个叶子节点和哪个策略组；
4. 节点属于哪个订阅；
5. 原始上传、下载、合计流量是多少；
6. 按订阅默认倍率或节点覆盖倍率折算后，预计计费流量是多少；
7. 其中多少由 `家庭测速` 产生。

功能必须适用于多个订阅。蜂鸟云只是第一份预置配置，统计引擎、API 和 UI 不得写死服务商名称。

## 2. 数据来源与精度

Router Admin 后台每秒读取：

```text
GET http://127.0.0.1:9091/connections
```

按连接 ID 保存上一张快照中的 `upload` / `download`，只累计非负增量。

- 采集器启动后的第一张成功快照只建立基线，不追记旧连接此前的字节。
- 后续首次出现的新连接，计入首次快照已经产生的字节。
- 本地重置时，以当前全部活动连接的当前计数建立新基线，防止旧流量再次计入。
- 连接计数器回退、Mihomo 重启、连接 ID 复用或元数据变化时，重新建立该连接的基线，不产生 uint 下溢或巨额虚假流量。
- Mihomo 离线后恢复时，第一张快照重新建立全部基线。
- 一秒内建立并关闭的短连接可能漏记；视频、下载和测速等长连接误差较小。
- 本地数据是 Mihomo 逻辑有效载荷。服务商可能计算代理封装、重传或采用不同计费口径，因此 UI 必须称为“预计计费流量”。

不得提高 Mihomo 日志等级、记录请求正文或读取订阅明文来换取精度。

## 3. 路由分类

每条连接按 `chains` 分类：

- 空链或包含 `DIRECT`：`routeKind=direct`；
- 包含 `REJECT`：`routeKind=reject`；
- 其他：`routeKind=proxy`，`chains[0]` 是实际叶子节点；
- 代理组取链中叶子节点之后最接近规则入口的非内建项；
- 链中包含 `家庭测速` 时设置 `speedtest=true`。

DIRECT、代理和 REJECT 都进入“观察到的流量”及设备维度，使 UI 能明确回答是否走节点。只有可归属订阅的代理流量进入该订阅的 VPN 合计和预计计费合计。无法归属订阅的代理流量单列为 `unassignedProxy`，绝不能误归到当前订阅。

`家庭测速` 流量必须同时计入对应订阅、设备、节点、组、时间桶及全局代理总量，并额外进入 `speedtest` 独立合计。它不是从正常总量中扣除的另一份流量。

## 4. 终端和目标

终端键优先使用 `metadata.sourceIP`：

- DHCP 租约存在时显示采集当时的主机名，同时保留 IP；
- `127.0.0.1` 显示“路由器本机 / CPA”；
- `198.18.0.1` 显示“Mihomo TUN 本机”；
- 空来源显示“路由器本机 / 来源未知”；
- 历史聚合保存采集时的名称，不因 DHCP 后续变化而重写。

目标优先保存规范化后的 `metadata.host`，为空时使用 `metadata.destinationIP`。不得保存 URL path、query、Authorization、订阅 URL、UUID、密码或节点凭据。

## 5. 订阅归属和倍率设置

复用现有 `~/router-data/mihomo/subscriptions.json` 的公开 ID 和名称，不复制或返回订阅 URL。

当前架构一次只加载一个活动订阅，因此连接首次进入账本时使用当时的 `activeId` 作为归属，并将订阅 ID、当时的显示名称、叶子节点固化到活动连接基线。订阅切换后，旧连接不得被重新归到新订阅。

设置文件按订阅维护：

```json
{
  "version": 1,
  "enabled": true,
  "subscriptions": {
    "subscription-id": {
      "defaultMultiplierMilli": null,
      "nodeMultipliersMilli": {
        "日本05 | 直连 | 移动": 1000
      },
      "knownNodes": ["日本05 | 直连 | 移动"]
    }
  }
}
```

- `knownNodes` 从当前 `家庭测速` 组和实际连接自动发现并去重，便于 UI 编辑；
- 倍率使用千分整数，例如 1×=`1000`、1.5×=`1500`、2×=`2000`，累计使用整数运算；
- 节点倍率优先于订阅默认倍率；
- 两者都未设置时仍累计原始流量，但进入 `unpricedRawBytes`，预计计费不得擅自按 1×计算；
- 合法范围 0.1×–100×，可清空节点覆盖以恢复订阅默认值；
- 节点名匹配前只移除开头的国旗 emoji 和两侧空白，其他字符精确匹配；
- 重命名订阅不得丢失统计，因为归属键是订阅 ID。

配置路径：

```text
~/router-data/mihomo/traffic-accounting-settings.json
```

不得修改现有订阅 URL、激活状态或 Mihomo 节点选择。

## 7. 聚合维度

每个聚合值包含 `uploadBytes`、`downloadBytes`、`rawBytes`、`weightedUploadBytes`、`weightedDownloadBytes`、`weightedBytes`、`unpricedRawBytes`、`connectionCount` 和 `lastSeenAt`。

至少提供：

- 全部观察流量；
- DIRECT、代理、REJECT、未归属代理；
- 按终端、订阅、节点、代理组、目标域名/IP；
- 按“终端 + 路由类型 + 订阅 + 节点 + 代理组”的交叉明细，使界面能直接回答某台终端是否走代理以及走了哪个节点；
- `家庭测速` 独立总计；
- 最近 24 小时小时桶、最近 90 天日期桶。

连接次数在连接 ID 首次进入当前统计周期时增加一次。目标最多持久化 5000 个键，设备、订阅、节点、组分别设合理上限；超出上限合并至 `_other`。API 对每张排行表返回前 200 行，其余合并，避免响应无限增长。

终端交叉明细使用复合内部键并设置 5000 行持久化上限。对 DIRECT/REJECT 行，订阅、节点和组为空；对代理行必须带采集时固化的订阅、叶子节点和代理组。相同节点名出现在不同订阅时不得合并。

## 8. 持久化和生命周期

账本路径：

```text
~/router-data/mihomo/traffic-accounting.json
```

要求：

- schema version，及 `startedAt`、`updatedAt`、`lastSuccessfulPollAt`；
- 成功、失败、连续失败和被拒绝快照计数；
- 每 10 秒或新增 1 MiB 时原子写临时文件再 rename；
- 文件权限 `0600`，目录 `0700`；
- Router Admin 重启后加载旧账本，首张快照只接续基线；
- 文件损坏时保留为 `.corrupt-时间戳`，新建空账本并通过 API/UI 警告；
- 任意定时落盘失败必须进入运行时健康状态并在 API/UI 中告警；后续成功落盘后才可清除，不得静默假装已经持久化；
- 活动连接 ID 不作为长期历史持久化；
- 服务退出时尽力落盘；
- 采集器默认随 Router Admin 启动并持续运行。

手动重置只清空本地账本，不调用服务商，不改订阅、不切换节点、不关闭连接。reset 与 poll 必须在同一互斥边界内串行化，并用当前连接计数建立新基线。

## 9. API

全部使用现有登录认证：

```text
GET  /api/mihomo/traffic-accounting
POST /api/mihomo/traffic-accounting/reset
GET  /api/mihomo/traffic-accounting/settings
PUT  /api/mihomo/traffic-accounting/settings
```

统计 GET 返回健康状态、统计起点、当前速率、各总计和受限排行，不返回连接 ID、完整控制器响应或订阅秘密。

PUT settings：

- 只接受 `enabled` 和按公开订阅 ID 组织的倍率设置；
- 严格拒绝未知字段、非法 ID、重复节点、过长名称及越界倍率；
- 不接受或返回订阅 URL；
- 修改倍率只影响修改后产生的增量，不追溯重算历史账本；
- 使用原子持久化。

POST reset 请求体必须小且严格解码，返回新的 `startedAt`。前端二次确认文案明确“只清空本地统计；请确认服务商侧也已重置”。

## 10. 前端

在 Router Admin“代理”页新增“流量审计”区域：

- 总览：统计起点、观察流量、代理原始流量、预计计费、DIRECT、家庭测速、当前代理速率和采集健康；
- 标签页：终端、订阅、节点、代理组、目标、时间；
- 每行显示上传、下载、原始合计、倍率/计价状态、预计计费、连接数；
- 可明确筛选 `direct` / `proxy` / `reject`；
- 未设置倍率、未归属订阅和采集异常醒目提示；
- “倍率设置”按订阅展示默认倍率及已发现节点覆盖，保存前说明只影响未来流量；
- 本地清空按钮带二次确认；
- 自动刷新不得阻塞现有状态、连接和测速接口。

移动端优先，表格在窄屏可横向滚动，不能破坏现有 Chrome 87 兼容构建。

## 11. 资源和安全边界

- 采样间隔默认 1 秒；
- 控制器请求超时不超过 800 ms；
- 响应体上限 16 MiB；
- 最多处理 10000 条活动连接，超过时整张快照拒绝，不能部分累计；
- 连续失败不影响 Router Admin 其他 API；
- 不重启 Mihomo、不切换节点、不关闭用户连接；
- 不在日志打印目标 URL、订阅 URL、凭据或完整连接快照；
- 所有累计使用溢出安全的 `uint64` 加法和倍率计算；
- 前端和 API 明确区分“原始流量”与“预计计费流量”。

## 12. 测试与验收

后端测试至少覆盖：

1. 首张快照只建基线；
2. 连续增量恰好累计一次；
3. 新连接首次字节计入；
4. 关闭、ID 复用、计数回退、Mihomo 离线恢复；
5. DIRECT / REJECT / 代理分类；
6. 活动订阅切换时连接归属不串订阅；
7. 终端、节点、组、目标和时间聚合；
8. `家庭测速` 单列且仍计入总量；
9. 节点覆盖、订阅默认、未知倍率和整数折算；
10. 设置修改只影响未来增量；
11. reset 与 poll 并发安全且不重复计费；
12. 原子持久化、0600 权限、损坏恢复和重启不重复；
13. 维度上限进入 `_other`；
14. API 不泄露订阅 URL、凭据或连接 ID；
15. 超大响应、超多连接、超时和整数溢出安全；
16. `go test ./...` 及关键并发测试重复通过。

前端必须通过 `npm run lint` 和 `npm run export`，仓库必须通过 `git diff --check`。

部署到手机前后记录 `家庭RULE`、`AI`、`Antigravity` 和 `家庭测速` 选择，确认完全不变。部署后立即执行一次本地 reset，记录精确 `startedAt`，再用一个很小的代理请求和一个 DIRECT 请求验证分类；不运行完整深度测速。

## 13. 本次基线

用户已在 2026-09-14 手工重置蜂鸟云服务端套餐流量。本地准确统计只能从新采集器部署并执行本地 reset 的时刻开始；服务商重置与本地启用之间的流量无法事后精确恢复，必须在交付说明和 UI 中标明。
